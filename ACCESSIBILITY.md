# Accessibility

This statement covers the LSCSS documentation website and the examples maintained in this repository.

## Our approach

We aim for WCAG 2.2 Level AA across the site's templates, navigation, typography, colour, and focus behaviour. This is a target; we do not claim full conformance or formal certification.

Our priorities are:

- Semantic HTML, meaningful headings, and native controls.
- Keyboard access, a logical focus order, and visible focus indicators.
- Readable text, sufficient colour contrast, and support for zoom and user preferences.
- Reduced motion support and progressive enhancement.

LSCSS is a CSS methodology. Accessibility also depends on the content, markup, and behaviour of each product that uses it.

## Current status and known limitations

The [website accessibility statement](https://lscss.crayonsandco.de/accessibility/) describes the site's conformance target and known limitations, including navigation and technical content. Keep that page as the detailed reference for the website's accessibility status.

## Report an accessibility problem

[Open a GitHub issue](https://github.com/pdincubus/LSCSS/issues/new) or contact us through [Crayons and Code](https://crayonsandco.de/).

Include whatever you can:

- The page URL or affected example.
- What you were trying to do and what prevented you from doing it.
- Your browser, operating system, and any assistive technology, with versions if known.
- Steps to reproduce the problem, and optional screenshots or recordings.

You can report a barrier without identifying a WCAG criterion or providing technical evidence. GitHub issues are public, so use the contact route for personal information.

## Contributing

Preserve keyboard access, accessible names, visible focus, logical headings, and reduced motion support. Check affected interactions with a keyboard and, where relevant, a screen reader, zoom, and user colour preferences. Describe the checks performed and any remaining limitations in your pull request.

See [Accessibility and CSS](https://lscss.crayonsandco.de/writing/guides/accessibility-and-css/) for guidance. Update the relevant statement when a change affects accessibility support, known barriers, or reporting routes.
